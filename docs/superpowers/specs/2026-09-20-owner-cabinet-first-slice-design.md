## 1. Цель

Собрать десктоп-кабинет владельца **пиксель-в-пиксель** по Figma для одного вертикального среза: вход в систему, список объявлений, мастер создания и отправка на модерацию. Остальные разделы кабинета видны в сайдбаре, но открывают заглушку.

PocketBase в этом срезе не подключаем. Данные живут в мок-адаптере (`localStorage`) за тем же интерфейсом API, который позже закроет PocketBase.

## 2. Границы среза

### Входит

- Стек: Vite + React + TypeScript + React Router, деплой статики через **Caddy** (nginx нет).
- Дизайн-система примитивов из Figma, затем экраны из этих примитивов.
- Авторизация: вход, регистрация, восстановление пароля (только UI + мок), онбординг профиля (фото необязательно; имя и телефон обязательны).
- Оболочка кабинета: сайдбар 235px, шапка, логотип GlobalStay.
- Список объявлений: вкладки «Все / Опубликованы / На модерации / Архив», поиск, пустое состояние, карточки.
- Кнопка «Импорт из TravelLine» — как в макете, по клику заглушка «Импорт появится позже».
- Мастер создания: 6 шагов + предпросмотр (`1:20382`) с действиями кадра: править, удалить, сохранить в архив, отправить на модерацию.
- Заглушки: `/bookings`, `/chats`, `/notifications`, `/profile` — каркас кабинета и текст «Раздел появится позже». На заглушке профиля есть «Выйти» (сброс мок-сессии).
- Узкое окно (< 1280px): полноэкранная заглушка «Откройте сайт с компьютера». Макет не сжимаем.
- Документация в `docs/` (см. §10).

### Не входит (следующие циклы)

- Настоящий PocketBase, SMS, почта, пуши.
- Бронирования, календарь занятости, чаты, уведомления, полноценный профиль, вывод средств.
- Интеграция TravelLine (кнопка и поле API-ключа не работают).
- Публикация объявления (это делает администратор). Мок не ставит статус `published`. Вкладка «Опубликованы» всегда с пустым состоянием.
- Клиентское приложение и админка.
- Адаптив планшет/телефон, кроме заглушки «откройте с компьютера».
- Секреты и admin-токен PB в клиенте — запрещены в любом цикле.

ТЗ целиком не реализуем. Этот файл — источник правды для **первого среза**; полное ТЗ остаётся картой продукта.

## 3. Архитектура

```
src/
  app/          маршруты, провайдер сессии, порог ширины окна
  ui/           Button, Input, Sidebar, Tabs, Search, ListingCard,
                EmptyState, Modal, WizardSteps
  pages/        экраны среза и заглушки разделов
  api/          интерфейсы AuthApi, ListingsApi + mock-адаптер
  config/       публичные константы (комиссия, ширина, бренд)
```

Правила слоёв:

- Страницы вызывают только `api/*`. Ни `localStorage`, ни PocketBase в компонентах.
- `ui/*` не знает про объявления и сессию — только пропсы.
- Мок и будущий PB-адаптер реализуют один интерфейс. Смена адаптера — правка одной фабрики, не экранов.

Сборка: `vite build` → `dist/`. Caddy на VPS отдаёт `dist` с `try_files` / `try_files {path} /index.html` для SPA. Dev-сервер Vite на VPS не выставляем.

Публичные env (префикс `VITE_`) — только то, что можно светить в DevTools: например будущий URL PB. Пароли, admin-токен PB, SMTP, платежи — никогда.

## 6. Компоненты

Собираем один раз в `ui/`, экраны только композируют:

- `Button` — заливка, контур, круглая иконка.
- `Input` — лейбл, поле, подсказка, ошибка (состояния как `Input_web`).
- `Sidebar`, `Tabs`, `Search`.
- `ListingCard` — фото, название, адрес, статус.
- `EmptyState` — иллюстрации пустого списка и пустых броней (вторая — на заглушке не обязательна).
- `Modal` — TravelLine, подтверждение удаления, успех модерации если в макете модалка.
- `WizardSteps` — шесть подписей: Описание, Фото, Удобства, Правила, Дополнительное, Стоимость.

Не подключаем Mantine/Ant как визуальную основу.

## 7. Данные

Интерфейс (имена ориентир, смысл фиксирован):

```ts
type ListingStatus = "draft" | "moderation" | "published" | "archived";

interface AuthApi {
  register(email: string, password: string): Promise<Session>;
  login(email: string, password: string): Promise<Session>;
  logout(): Promise<void>;
  completeOnboarding(input: { name: string; phone: string; photo?: string }): Promise<Session>;
  requestPasswordReset(email: string): Promise<void>;
  confirmPasswordReset(token: string, password: string): Promise<void>;
}

interface ListingsApi {
  list(filter: { tab: "all" | "published" | "moderation" | "archived"; query: string }): Promise<Listing[]>;
  get(id: string): Promise<Listing>;
  saveDraft(listing: ListingDraft): Promise<Listing>;
  submitForModeration(id: string): Promise<Listing>;
  archive(id: string): Promise<Listing>;
  remove(id: string): Promise<void>;
}
```

Мок:

- Ключи `localStorage`: `gs.session`, `gs.users`, `gs.listings`.
- Пароли в моке храним только как демо (не продакшен-хеш); в UI это не светим. При смене на PB мок удаляется.
- Созданное объявление переживает перезагрузку вкладки.
- Старт с пустым списком. Сидов нет.
- Фото пишем в `localStorage` как data URL. Перед записью сжимаем (JPEG, длинная сторона ≤ 1600px), иначе шесть снимков не влезут в квоту. Если квота всё равно превышена — баннер из §8, шаг не считаем сохранённым.
- Комиссия: `SERVICE_COMMISSION_RATE = 0.09`. Владелец вводит **базовую** цену за сутки. На кадре три числа: база, `commission = Math.round(base * rate)`, цена для клиента `base + commission`. Цифры 3500 / 320 в Figma — макетный пример (у нас 3500 → 315 → 3815). Вёрстку сверяем с кадром, числа — с константой. Ставку не хардкодим в JSX.

Поля объявления в мастере (обязательность — как валидация шага):

1. **Описание:** название, адрес, вид жилья (селект), описание (лимит 500).
2. **Фото:** минимум 6 файлов; меньше — шаг не закрывается.
3. **Удобства:** набор чипсов из макета (можно снять/поставить).
4. **Правила:** макс. гостей, животные да/нет, отмена брони да/нет, время заезда/выезда.
5. **Дополнительное:** как попасть внутрь, правила проживания, доп. информация (свободный текст, лимиты как на кадре).
6. **Стоимость:** три базовые цены — сутки; от 14 дней; от 28 дней. Для каждой — комиссия и цена для клиента (§7). Тоггл «уникальная стоимость для дат» — блок как в макете, те же три числа на каждую дату.

Предпросмотр читает черновик и рисует кадр `1:20382`.  
«Отправить на модерацию» → `status: moderation`, экран/состояние `1:22257`, запись на вкладке «На модерации».  
«Сохранить в архив» → `status: archived`.  
«Править» с предпросмотра → `/listings/:id/edit`. После первого «Далее» у нового объявления появляется id, дальше мастер живёт на `/listings/:id/edit`.

TravelLine и заглушки разделов **не** вызывают `ListingsApi` / `AuthApi`, кроме «Выйти» на профиле (`logout`).

## 8. Ошибки и крайние случаи

- Неверный логин — ошибка у поля, как состояния кадров входа.
- Пустые обязательные поля — ошибка у поля; если в Figma нет текста, используем короткий русский («Обязательное поле»).
- Меньше 6 фото — «Добавьте ещё N фото».
- Переполнен `localStorage` — баннер «Не удалось сохранить, попробуйте ещё раз», черновик не считаем принятым.
- Битая JSON-сессия — logout и `/login`.
- Неизвестный `:id` предпросмотра — редирект на `/listings`.
- Узкое окно — только заглушка.

Письма нет. После ввода email показываем кадр успеха и на нём же демо-ссылку «Задать новый пароль» → `/reset-password?token=...` (токен выдаёт мок). Отдельной почтовой системы нет.

## 9. Тесты

Автотесты (Vitest):

- мок: регистрация, вход, ошибка входа, онбординг, черновик, модерация, архив, фильтр вкладок, поиск по названию/адресу;
- комиссия: `Math.round(3500 * 0.09) === 315`; формула только в `config`, не в компоненте;
- гарды маршрутов — юнит на функции `requireAuth` / `requireOnboarding`, не обязателен полный router e2e.

Ручная сверка с Figma: вход, регистрация, онбординг, пустой список, мастер все 6 шагов, предпросмотр, успех модерации, вкладка «На модерации», заглушки сайдбара, окно < 1280px.

E2E-стенд (Playwright и т.п.) в срез не входит.

## 11. Безопасность (этот срез)

- Нет `VITE_` с секретами.
- Source maps в production-сборке выключены.
- Мок в `localStorage` — только этот браузер; это не продакшен-хранилище ПДн.
- Когда появится PB: в клиенте сессия пользователя, не admin-ключ; доступ режут правила коллекций.

## 12. Критерий готовности среза

1. Экраны §5 визуально совпадают с указанными кадрами на ширине 1440.
2. Можно зарегистрироваться, заполнить имя и телефон, создать объявление и увидеть его «На модерации» после перезагрузки.
3. TravelLine и чужие пункты сайдбара открывают заглушку, не ломая сессию.
4. На ширине 1279px кабинет не показывается.
5. Документы §10 на месте, в README нет секретов.
6. Тесты §9 зелёные.

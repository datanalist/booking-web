# GlobalStay — кабинет владельца

Веб-кабинет владельца жилья. Макет — секция «Веб-сайт для владельцев жилья» в [Figma Booking](https://www.figma.com/design/zqPAmK0qrRQtqMp5IP3K5u/Booking?node-id=1-16219). Прод-домен: `app.booking.vallome.ru`.

Стек: Vite + React + TypeScript + React Router + Vitest + Tailwind CSS v4. Прод: Docker-контейнер с Node-сервером `server/server.ts` (статика `dist/` + файловое хранилище фото) за Caddy (nginx нет). См. «Прод и CI/CD».

## Первый срез

Вход / регистрация / восстановление пароля, онбординг, список объявлений, мастер из 6 шагов, предпросмотр и отправка на модерацию. Чаты — демо-переписки из сида (см. ниже). Страница `/notifications` при пустом ящике показывает макет Figma 1:18177: иллюстрация `public/notifications-empty.svg`, «Нет уведомлений» и «Уведомления об объявлениях и бронированиях появятся здесь», без вкладок. PocketBase не подключаем — моки в `localStorage`. Мок не ставит `published`. При `VITE_DATA_SOURCE=pocketbase` страница читает коллекцию `notifications` текущего пользователя (`user`, сортировка `-created`). Непрочитанные (`read` не true) с красной точкой 7px `#E34043`. Прочитанные без точки. Мок-списка уведомлений нет. Вкладка «Не прочитанные» (`/notifications?tab=unread`) показывает записи с `read !== true`. Пустая вкладка — иллюстрация и «Все уведомления прочитаны». Вкладка «Прочитанные» (`/notifications?tab=read`) повторяет список непрочитанных и показывает только `read = true`, без красной точки. Бейдж «Уведомления» в сайдбаре — число непрочитанных, а клик по карточке помечает эту запись PocketBase прочитанной. Клик не пишет `host_last_read` и не снимает непрочитанные в списке чатов.

Регистрация требует галочку условий, а вход паролем — подтверждённую почту по кнопке из письма. Кнопка открывает пустую страницу с уведомлением по центру окна: «Ваша почта подтверждена. Пожалуйста, вернитесь на страницу входа.» Уже открытая регистрация сама переходит на вход и показывает, что почта подтверждена. Уже открытый вход остаётся на месте и показывает то же. Сигнал между вкладками лежит в `src/pages/emailVerifiedNoticeChannel.ts`, отдельно от экрана `EmailVerifiedNotice.tsx`: на Windows одинаковое имя с разным регистром заставляет Vite открыть `.ts` вместо компонента, и страница не монтируется. Неверный пароль остаётся обычной ошибкой входа и не сообщает, что почта не подтверждена. Истёкший токен PocketBase (поле `exp`) и ответ `401` с этим токеном стирают сессию и открывают `/login`, в том числе если срок наступил, пока кабинет уже был открыт. Токен без `exp` сессию не сбрасывает. Запись в мок-хранилище без поля `verified` по-прежнему входит. Миграция `pb_migrations/1792433000_verify_existing_users.js` помечает уже существующих пользователей подтверждёнными; откат никого не снимает. Если письмо не ушло, регистрация показывает «Не удалось отправить письмо. Попробуйте ещё раз».

При `VITE_DATA_SOURCE=pocketbase` на `/login` под кнопкой «Начать работу» стоит подпись «или войдите с помощью» и квадратная кнопка-иконка Telegram (подпись «Войти через Telegram»). Кнопка открывает окно `https://oauth.telegram.org/auth` с `client_id` из `VITE_TELEGRAM_BOT_ID` и `redirect_uri` `https://app.booking.vallome.ru/`. Страница получает `id_token` и отправляет его на хук `POST /api/vallome/telegram-auth`. Хук сверяет подпись RS256 с публичным ключом Telegram и аудиторию с id из `TELEGRAM_BOT_TOKEN`, не ходя на `oauth.telegram.org`. Новая запись получает `roles: ["host"]` и `account_status: "active"`. Пустая почта вход не блокирует. Номер телефона у Telegram не запрашивается: без телефона кабинет открывает онбординг. В мок-режиме кнопки нет. В BotFather в Trusted Origins и Redirect URIs указан `https://app.booking.vallome.ru/` — слэш в конце дописывает сам BotFather.

## Профиль

Экран `/profile` (фича `src/features/profile/`, публичный API — только `ProfilePage`): шапка с кнопками «Редактировать», «Выйти» и «Написать в поддержку» (в моке открывает `/chats?chat=chat-support`; при PocketBase открывает уже существующий чат поддержки этого хозяина или создаёт один и открывает его) и три колонки в белой карточке `rounded-2xl`:

- `personal-card/` — фото 300×244 (без фото — иллюстрация пустого состояния) и три поля только для чтения: имя, телефон, email; данные из сессии.
- `api-key-card/` — «API Key TravelLine» в трёх состояниях: не подключено, «Подключено» (`#4aa446`), «Ошибка подключения» (`#e34043`). Кнопка «Подключить» — пилюля `rounded-[30px]`. Подключение — мок `connectApiKey`: ключ из цифр длиной от 6 → подключено, иначе ошибка (настоящего API TravelLine нет).
- `balance-card/` — «Доступный баланс» (`session.balance ?? 34 670 ₽`, связан с `users.balance` в PocketBase) на фоне `public/profile/balance-lines.svg`, кнопка «Вывести средства» (`rounded-[30px]`) пока заглушка.
- `edit-profile-modal/` — алерт «Редактировать данные профиля» (фото через кроп, «Удалить фото», имя, телефон, email, кнопка «Сохранить» с `rounded-lg`). Сохранение вызывает `auth.updateProfile`: запись пользователя и сессия в `localStorage` обновляются, карточка и сайдбар сразу показывают имя, email и фото. Занятый email (`EMAIL_TAKEN`) и другие ошибки полей оставляют алерт открытым.
- `logout-modal/` — алерт «Выйти из аккаунта?» с равными по ширине кнопками «Вернуться» и «Да, выйти» (`rounded-lg`); подтверждение вызывает `auth.logout()` и ведёт на `/login`.

Ассеты из Figma лежат в `public/profile/` (`balance-lines.svg`, `photo-empty-illustration.svg`, иконки `icon-*.svg`). Полупрозрачные заливки и обводки взяты из Dev Mode: `rgba(251,192,40,0.06)` и `rgba(251,192,40,0.17)`; акцент `#f88a2a`.

Экран «Мои объявления» (`/listings`) — **один экран с четырьмя вкладками** над общим списком (контекст `AllListingsProvider` выше роутов кабинета, без API; список сохраняется в `localStorage` под ключом `gs.allListings`, см. ниже): «Все объявления», «Опубликованы», «На модерации», «Архив». Шапка с «Импорт из TravelLine» и «Создать объявление», поиск по названию/адресу, таблица и бейджи статусов по макетам Figma. Мок — 8 строк со смешанными статусами (в т.ч. «Апартаменты для семьи» среди опубликованных). В колонке названия — главное фото объявления (у мока кадры из макета, у сохранённого черновика — первый кадр галереи). Код — `src/features/listings/` (публичный API через `index.ts`). Удаления и смена статусов сохраняются при уходе в мастер редактирования, возврате назад и перезагрузке страницы.

Ветка `fix-seed-dev-test` чинит вкладку объявлений: фото галереи в превью, бейдж «Снято с публикации» в одну строку, настоящее удаление, корзину в превью, пункт меню «Календарь бронирования», отправку черновика на модерацию и кнопку «Далее» у опубликованного объявления на шагах описания, фото, удобств, правил, дополнительных сведений и стоимости.

Правое фото экранов входа и регистрации (`public/auth-side.jpg`) — полный кадр без белых полей. Скругление 20px со всех четырёх углов задаёт вёрстка, а не сам файл.

UI-примитивы кабинета — `src/ui/`. Логотип GlobalStay в сайдбаре — картинка 181×60 у нижнего края колонки (left 27, 32px от низа). Колонка тянется на высоту окна. Шапка профиля — 96px на всю ширину колонки, отступы 32×24, аватар 40px, имя `text-sm font-bold leading-5`, почта `text-xs leading-4 text-neutral-600`; длинная почта обрезается внутри колонки и не вылезает за 235px. Пункты сайдбара переключают раздел внутри приложения, без полной перезагрузки страницы. Знак этого логотипа стоит во вкладке браузера: `public/favicon.svg`. Шрифт Noto Sans подключается из `index.html` отдельно от `src/index.css`, чтобы общий лист стилей не ждал Google Fonts. Документация среза: [`docs/architecture.md`](docs/architecture.md), [`docs/screens.md`](docs/screens.md), [`docs/data-adapter.md`](docs/data-adapter.md).

### Фильтр вкладок и живые действия меню

Фильтр вкладки по статусу одной и той же строки: Все — все статусы; Опубликованы — «Опубликовано»; На модерации — «На модерации»; Архив — «Снято с публикации».

Меню «⋯» открывается порталом слева от кнопки (зазор 3px, верх по первой точке иконки), без обрезки overflow таблицы. Пункты зависят от статуса:

- **Опубликовано:** «Календарь бронирования» без перехода; «Редактировать» → существующий мастер `/listings/:id/edit?step=1` (если черновика в `gs.listings` ещё нет, мастер сидирует его из строки таблицы через `ensureForEdit`); «Снять с публикации» → диалог, «Да, снять» ставит «Снято с публикации» (строка остаётся на «Все», появляется в «Архив», исчезает с «Опубликованы»); «Удалить» → диалог.
- **На модерации:** только «Удалить» → диалог; «Да, удалить» убирает строку отовсюду (кнопка в одну строку).
- **Снято с публикации:** «Редактировать» → тот же мастер `/listings/:id/edit?step=1`; «Опубликовать» → диалог (макет Figma 1:22505, ширина 438px, кнопки `whitespace-nowrap`), «Да, опубликовать» ставит «Опубликовано» (строка уходит из Архива, появляется на «Опубликованы», на «Все» остаётся); «Удалить» → диалог.

Отмена диалогов (Вернуться / крестик / Escape / затемнение) данные не меняет.

Сортировка по статусу поднимает выбранные статусы наверх и оставляет остальные строки ниже в исходном порядке (в меню нет пункта «Запрос»; при «Все» порядок исходный). Меню «⋯» у статусов без действий disabled.

Меню «⋯» во вкладке «Подтверждены» (`confirmed/menu/`) — один пункт по статусу: «Оставить отзыв» (аренда завершилась; после отправки — «Отзыв оставлен»), «Отменить бронирование» (ожидание предоплаты; модалка с причиной) и «Открыть» (запрос: модалка запроса на отмену или на изменение сроков). При `VITE_DATA_SOURCE=pocketbase` отзыв хозяина о госте пишется в коллекцию `reviews` (`kind=guest`, одна запись на бронь); «Отзыв оставлен» показывается только если такая запись есть, а при ошибке сохранения пункт не меняется. В моке тот же `bookingReviewsStore` заполняется сразу. Открытым может быть только одно меню: id открытой строки хранится на уровне панели (`id | null`), меню закрывается по клику вне, Esc, прокрутке/ресайзу и при открытии модалки. Модалки живут в своих папках (`review/`, `cancel/`, `request/`) и открываются через единый диалог-хост; у всех одна фокус-ловушка (`dialog/useDialogFocusTrap`). Статус «Запрос» хранит предыдущий статус брони (`previousStatus`, тип без самого «Запроса»): «Отклонить» возвращает строку в него; принятый запрос на изменение сроков применяет новые даты и цену. Куда уходит отклонённый запрос, задаёт одно значение `rejectedRequestDestination` (сейчас — возврат статуса, а не запись в «Отменены»).

«Отклонены» (`?tab=rejected`) — таблица без кнопок принять/отклонить и без колонки статуса: ФИО с портретом, чат-конверт, жильё с фото `public/bookings/housing-*.jpg` 48×48 `rounded-lg`.

«Отменены» (`?tab=cancelled`) — таблица без кнопок, статуса и сортировки. Шапка `bg-amber-400/20`, `h-12`, `font-bold` (ФИО `w-56`, Чат `w-16`, Жилье `w-72`, Даты `w-36`, Стоимость `w-28`). Строки `h-28`, текст ячеек `font-normal` без обводки: имя и жильё `text-sm`, телефон и адрес `text-xs text-neutral-600`; аватар 48px, конверт outline 24px, фото жилья 48px с `p-1`. Источник — стор отменённых: к мокам сверху добавляются брони, отменённые владельцем из «Подтверждены» и принятые запросы на отмену (гость, жильё, даты, стоимость; причина и инициатор не показываются). Сторы подтверждённых и отменённых живут в памяти модуля и переживают переключение вкладок без перезагрузки страницы.

При `VITE_DATA_SOURCE=pocketbase` демо-строки не появляются до ответа сервера: область таблицы пустая, затем все вкладки, включая «Отклонены», показывают снимок PocketBase.

`?empty=1` и поиск без совпадений показывают пустой стейт текущей вкладки. Пустое состояние всех вкладок показывает иллюстрацию из макета. Поиск: «Введите имя или номер гостя».

## Мастер объявления

Шесть шагов: описание, фото, удобства, правила, дополнительные сведения, стоимость. Холст шага — отступ 32px от сайдбара (`p-8`), без отрицательных полей. Шаг «Удобства» использует `lucide-react`: после переключения на ветку нужен `npm install`.

После шага 6 — **предпросмотр** `/listings/:id/preview` (макет Figma 1:20382): данные из черновика `gs.listings` (пустые поля подставляются демо из макета; если гости запрещены, в карточке «Количество гостей» — «Запрещено», а не демо «4 человека»). Кнопки: назад → шаг 6 мастера; карандаш → `/listings/:id/edit?step=1`; корзина → диалог удаления и возврат в список; «Сохранить в архив» → в «Архив» со статусом «Черновик» (меню без «Опубликовать»; «Снято с публикации» остаётся у снятых с публикации); «Отправить на модерацию» → статус «На модерации» и алерт Figma 1:22257 («Ок» / крестик → вкладка «На модерации»).

### Предпросмотр по клику из «Мои объявления»

Клик по строке открывает `/listings/:id/preview`. Бейдж статуса и кнопки в шапке зависят от статуса:

### Календарь бронирования

Алерт на Radix AlertDialog (`@radix-ui/react-alert-dialog`). Открывается иконкой «Перейти в календарь бронирования» в шапке предпросмотра опубликованного объявления и пунктом меню в списке; закрывается крестиком и Escape. Шапка (название, город и адрес, обложка) читается из записи `listings` по id объявления. Справа — брони выбранного месяца в статусах `pending_host`, `awaiting_prepayment`, `confirmed` и `change_requested`: имя, телефон и аватар гостя из `expand.guest`. `cancelled`, `completed` и `cancel_requested` в список и в занятые дни не попадают. Занятые ночи — полуинтервал `[check_in, check_out)` плюс запрошенные даты, если они заданы. Недоступные дни и переключатель «доступно для бронирования» читают и записывают коллекцию `listing_blocks` токеном вошедшего хозяина. Если занимающих броней нет, список гостей пустой. До ответа сервера демо-гости не появляются. Кнопки «написать» и «удалить» запись брони не меняют.

### Хранение данных

- Список объявлений кабинета — `localStorage`, ключ `gs.allListings`; в хранилище пишутся лёгкие строки, при переполнении квоты — повторно без обложек (без исключений). Мастер при переполнении показывает ошибку про фото.
- Фото — файловое хранилище в `./data/` через Vite middleware (`vite/dataStorePlugin.ts`): `POST /api/files` (загрузка, ответ — имя `<uuid>.<ext>`), `GET /data/<uuid>.<ext>`, `DELETE /api/files/<uuid>.<ext>`. Работает в `npm run dev`, `npm run preview` и на проде через `server/server.ts`; **не** в чисто статической раздаче `dist/`. Содержимое `data/` в `.gitignore` (отслеживается только `data/.gitkeep`).

### Мастер: «Назад» и степпер

Стрелка «Назад» в шапке мастера на всех шагах ведёт в «Мои объявления» на вкладку-источник, откуда пользователь пришёл (`/listings`, если вкладка неизвестна); несохранённые правки сохраняются, если объявление уже создано. Возврат на предыдущий шаг — кнопка «Вернуться» внизу формы (изменённый черновик сохраняется, при ошибках валидации шага остаётся на месте). Степпер показывает шесть шагов: пройденные, текущий и предстоящие, заливка до текущего шага.

Кабинет по-прежнему работает с мок-хранилищем по умолчанию, при этом все поля сайта связаны двусторонними мапперами и HTTP-клиентом с коллекциями и хуками PocketBase (`src/api/pocketbase/`, `src/features/bookings/pocketbase/`, `src/features/chat/pocketbase/`; подробнее — в [`docs/data-adapter.md`](docs/data-adapter.md) и [`docs/pocketbase-schema.md`](docs/pocketbase-schema.md)). Спеки и планы в репозиторий не входят.

## Чаты

Экран `/chats`. Если в сиде есть переписки, слева список (`ChatsScreen`), справа открытый чат (`ChatConversation`) после выбора строки. Если переписок нет — прежний экран «Нет чатов».

Единый источник демо — `src/features/chat/data/chatSeeds.ts` (чат «Поддержка» и четыре гостя: Екатерина, Игнат, Анна, Илья). Кнопка профиля «Написать в поддержку» в моке открывает `/chats?chat=chat-support`: в списке и справа выбран этот чат. При `VITE_DATA_SOURCE=pocketbase` та же кнопка ищет чат `kind=support` с `host` текущего пользователя и открывает `/chats?chat=<id>`. Если записи нет, создаёт её от имени хозяина (`guest` и `host` — он, `staff` — учётка «Поддержка», если правило пускает) и открывает её. Второй чат поддержки тому же хозяину не создаётся. Список в `chatThreadMocks.ts` не хранит превью, время и бейдж отдельно: они считаются из последней реплики и пометок `receipt: "unread"` в сиде (у поддержки время строки списка задано отдельно, 13:40). Ленту сообщений собирает `chatMessagesFromSeed`, и пометка прочтения остаётся на реплике. Непрочитанное входящее в ленте — медовая заливка и жёлтая рамка; прочитанное чужое остаётся белым. У открытой строки списка бейджа нет: он гаснет в момент выбора. Фото — статические ассеты `chatAssets.messagePhoto` (помещение у лифта у Екатерины) и `chatAssets.listingCover` (двор у Анны), не файловое хранилище `./data/`. У Екатерины два непрочитанных сообщения гостя, у остальных бейджа нет. Демо-реплики датированы 10 сентября.

Живой кабинет (`VITE_DATA_SOURCE=pocketbase`) слушает SSE `/api/realtime` по коллекциям `messages` и `chats`. Новое входящее сразу меняет превью, время и жёлтый счётчик, не дожидаясь перезагрузки; в открытой переписке оно дописывается в ленту. Отметка прочтения пишет `host_last_read` и не двигает строку. Она же ставит `read: true` уведомлениям этого хозяина с тем же `notifications.chat`. Прочтение уведомления чат не помечает. Порядок списка — время последнего сообщения (`last_message_at`), не время правки записи.

Аватары живого чата берутся из аккаунтов, не из портретов макета. Свои сообщения показывают фото текущего пользователя (`users.avatar`); если файла нет или ссылка на него не открывается — силуэт `/onboarding/avatar-placeholder.svg`, тот же, что в сайдбаре и у гостя без файла. Стоковый `/avatar-placeholder.png` фото не считается. Та же проверка — на аватаре собеседника в чате и на портрете гостя в бронированиях и календаре объявления. Фото и имя собеседника в списке и в шапке — из его записи `users`. Карточка справа — название, город и обложка объявления, даты и число гостей связанной брони. У чата поддержки без файла аватара остаётся значок поддержки. Демо-сид по-прежнему рисует портреты из `chatAssets`.

Чтобы изменить демо, правьте `chatSeeds.ts` и пересоберите. Отдельного сброса нет: сид зашит в код, в `localStorage` чаты не пишутся. Текст и фото, отправленные из поля ввода, живут только в памяти открытой страницы и пропадают при перезагрузке. Длинный текст без пробелов переносится в поле ввода и в пузыре; явные переводы строк в пузыре сохраняются.

## Прод и CI/CD

Кабинет работает на мини-ПК рядом с PocketBase: `https://app.booking.vallome.ru` → Caddy → `127.0.0.1:8080` (контейнер `booking-web`).

- `Dockerfile` — многоэтапная сборка (`npm ci`, `npm run build`, затем Node 24.13 запускает `server/server.ts`). Версия Node зафиксирована: более новый npm отклоняет текущий `package-lock.json`. `VITE_DATA_SOURCE` и `VITE_POCKETBASE_URL` вшиваются при сборке (build-args, по умолчанию `pocketbase` и `https://pb.booking.vallome.ru`). `.env.local` в образ не попадает.
- `server/server.ts` — отдаёт `dist/` с SPA-fallback и тем же middleware, что в Vite: `POST/DELETE /api/files`, `GET /data/:name`. `GET /healthz` — проверка здоровья.
- `deploy/app/docker-compose.yml` — фото лежат в `/opt/booking-web/data` на хосте и переживают деплой.
- `deploy/minipc/caddy/Caddyfile` — блок `app.booking.vallome.ru`.
- `.github/workflows/deploy.yml` — на PR и push в `main` идут тесты и сборка на GitHub-hosted runner. После push в `main` job `deploy` запускается на self-hosted runner мини-ПК (метка `minipc`): собирает образ, поднимает контейнер, проверяет `/healthz`, при сбое возвращает образ `booking-web:previous`.

Разовая настройка мини-ПК:

1. `sudo mkdir -p /opt/booking-web/data && sudo chown 1000:1000 /opt/booking-web/data`.
2. Self-hosted runner: GitHub → Settings → Actions → Runners → New runner (Linux x64), метка `minipc`, `./svc.sh install && ./svc.sh start`. Пользователь runner состоит в группе `docker`.
3. Скопировать обновлённый `Caddyfile` в `/etc/caddy/Caddyfile`, `sudo systemctl reload caddy`.
4. В `/opt/pocketbase/.env` задать `CABINET_URL=https://app.booking.vallome.ru` и перезапустить PocketBase (ссылка подтверждения почты).
5. Необязательно: переменная репозитория `VITE_POCKETBASE_URL` (Settings → Variables), если адрес PB меняется.

Откат вручную: `docker tag booking-web:previous booking-web:latest && cd deploy/app && docker compose up -d --no-build`.

## Секреты

В репозитории секретов нет: не кладём `.env`, admin-токен PocketBase, пароли и белый IP. Публичный URL API можно держать в коде или в `VITE_*` без секретов. Локальная папка переноса `.secrets/` закрыта `.gitignore` и в коммиты не входит.

## Новая машина

Актуальная ветка — `dev-dns_local`. В неё уже влиты `feat/pb-docker-schema`, `feat/pb-jsvm-hooks` и `feat/minipc-infra`. `main` и `dev` — более ранние линии; для кабинета и мини-ПК оставаться на `dev-dns_local`.

```bash
git clone git@github.com:datanalist/booking-web.git
cd booking-web
git checkout dev-dns_local
npm install
```

Файлы с секретами в git не входят, их кладут вручную:

- веб-кабинет — `.env.local` в корне репозитория и `src/app/localDevAuth.local.ts` (оба закрыты `.gitignore`);
- локальный compose PocketBase — `deploy/pocketbase/.env` из шаблона `deploy/pocketbase/.env.example`; пароль в шаблоне пустой. Символ `$` в значениях пишется как `$$`: Docker Compose иначе стирает его при пересоздании контейнера.
- пачка ключей и паролей для переноса машины — каталог `.secrets/` в корне. В git его нет.

Фильтры fail2ban разбирают JSON-время Caddy так: `datepattern = {EPOCH}`. Каталог полей — [`docs/pocketbase-schema.md`](docs/pocketbase-schema.md). Runbook старого VPS с живыми адресами в репозиторий не входит.
